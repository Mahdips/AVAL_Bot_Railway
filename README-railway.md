# AVAL BOT — استقرار روی Railway

این پوشه نسخهٔ اختصاصی Railway است و **کاملاً از نسخهٔ GitHub جدا است**.
چون Railway فقط **یک پورت عمومی** و **یک پروسه** می‌دهد، ربات تلگرام و وب‌پنل داخل یک event loop واحد اجرا می‌شوند (`WEB_WITH_BOT=1`).

---

## پیش‌نیازها

1. اکانت رایگان [railway.app](https://railway.app) (۲۴ دلار اعتبار آزمایشی)
2. توکن ربات از @BotFather (**توکن قبلی در چت فاش شده بود — حتماً یک توکن جدید بگیر**)
3. آیدی عددی تلگرام خودت (از @userinfobot)

---

## مراحل استقرار

### ۱) نصب Railway CLI و ورود

Railway CLI روش رسمی برای آپلود مستقیم کد از روی سیستم خودت است (بدون گیت‌هاب):

```bash
npm install -g @railway/cli@latest
railway login
```

> اگر خطای EACCES در ویندوز گرفتی، Command Prompt یا PowerShell را **به‌صورت ادمین**
> باز کن و دوباره `npm install -g @railway/cli@latest` را بزن.

مرحلهٔ ورود:
- اگر مرورگر باز شد، روی **Authorize** کلیک کن
- اگر روی سرور بدون مرورگر هستی، یک کد بهت داده می‌شه که از دستگاه دیگه‌ای وارد کنی
- روی سیستم خودت با `railway login --browserless` هم می‌توانی کد بگیری

### ۲) آپلود و دیپلوی کد

```bash
cd aval-bot-railway
railway up
```

این دستور پوشه را فشرده و آپلود می‌کند، سپس لاگ‌های build را به‌صورت زنده
نشان می‌دهد. `Dockerfile` به‌طور خودکار پیدا می‌شود و پروژه ساخته می‌شود.

> اگر پرسید «create a new project / link an existing one»، **Create new project**
> را انتخاب کن.

همین. اگر ترجیح می‌دهی پروژه را از قبل در پنل ساخته و به آن وصل شوی:
```bash
railway init       # پروژه خالی بساز
railway link       # به پروژهٔ موجود وصل شو
railway up
```

بعد از پایان build: `railway open` پنل را در مرورگر باز می‌کند.

### ۳) تنظیم متغیرهای محیطی (قبل از اولین deploy)
اگر `railway up` را بدون این متغیرها اجرا کنی، ربات بالا می‌آید ولی تلگرام کار نمی‌کند.
برای راحتی، متغیرها را با CLI از همین پوشه تنظیم کن:

```bash
railway variables set BOT_TOKEN=<توکن_جدید> ADMIN_IDS=<آیدی_تو> WEB_ADMIN_PASSWORD=<رمز_قوی>
```

یا از پنل: تب **Variables** در سرویس → **New Variable**:

| کلید | مقدار |
|---|---|
| `BOT_TOKEN` | توکن جدید از BotFather |
| `ADMIN_IDS` | آیدی عددی تلگرام خودت |
| `WEB_ADMIN_PASSWORD` | یک رمز قوی برای ورود به پنل |

> این مقادیر را **هرگز در چت یا GitHub قرار نده**. مستقیماً در پنل Railway وارد کن.

سپس دوباره `railway up` بزن تا با متغیرها build شود.

### ۴) ساخت Volume دائمی (مهم)
بدون این مرحله، هر بار redeploy کل دیتابیس (کاربران، سفارش‌ها، تنظیمات پنل) پاک می‌شود:

1. تب **Settings → Volumes → Add Volume**
2. مسیر mount: `/app/data`
3. تأیید کن

> نکته: اعتبار آزمایشی Railway شامل یک حجم ۱ گیگابایتی است. دیتابیس این ربات
> در حد چند مگابایت می‌ماند، پس جای نگرانی نیست.

### ۵) کاهش مصرف اعتبار آزمایشی (اختیاری ولی پیشنهاد می‌شود)
اعتبار آزمایشی محدود است. این تنظیمات مصرف را پایین نگه می‌دارند:

در تب **Settings → Resources**:
- **CPU**: به `0.25 vCPU` کاهش بده (پیش‌فرض بالاتر است)
- **RAM**: به `256 MB` کاهش بده

در تب **Variables** این را اضافه کن:
- `BACKUP_INTERVAL_HOURS` = `12` (به‌جای ۶ — بک‌آپ کمتر، ولی هنوز روزی ۲ بار)

با این تنظیمات، مصرف ماهانه حدود **۳ تا ۵ دلار** می‌شود و اعتبار ۲۴ دلاری
بیشتر از یک ماه دوام می‌آورد.

### ۶) گرفتن آدرس عمومی
1. تب **Settings → Networking → Generate Domain**
2. Railway یک زیردامنه رایگان می‌دهد، مثلاً:
   ```
   https://aval-bot-railway.up.railway.app
   ```

آدرس پنل مدیریت:
```
https://aval-bot-railway.up.railway.app/admin
```

### ۷) باز کردن پورت
Railway به‌طور خودکار پورت داخل Dockerfile (`8090`) را تشخیص می‌دهد. اگر پرسید، پورت را `8090` وارد کن.

## بعد از استقرار

به محض بالا آمدن، ربات یک پیام «نصب با موفقیت» برای `ADMIN_IDS` می‌فرستد که آدرس پنل توش هست. اگر این پیام را دریافت کردی، همه‌چیز کار می‌کند.

برای بررسی خطاها: تب **Deployments → View Logs**

## محدودیت‌های Railway (در مقایسه با سرور)

| امکان | سرور (نسخه GitHub) | Railway |
|---|---|---|
| Start/Stop/Restart از پنل | ✅ | ❌ — Railway خودش پروسه را مدیریت می‌کند |
| حذف ربات از پنل | ✅ | ❌ |
| اعمال سریع تغییر توکن | ✅ (restart می‌کند) | ⚠️ فقط ذخیره می‌شود؛ باید redeploy کنی |
| بک‌آپ هر ۶ ساعت در تلگرام | ✅ | ✅ |
| پنل مدیریت وب | ✅ | ✅ |
| دیتابیس دائمی | ✅ | ✅ (با Volume) |

بخش «کنترل Bot و تنظیمات» در وب‌پنل روی Railway به‌جای خطا دادن، پیام می‌دهد که این عملیات روی این پلتفرم در دسترس نیست. تغییر توکن/رمز همچنان کار می‌کند ولی برای **اعمال** آن باید سرویس را redeploy کنی.

## قیمت روی اعتبار آزمایشی

با تنظیمات پیشنهادی بالا (۰.۲۵ vCPU، ۲۵۶ MB رم): حدود **۳ تا ۵ دلار در ماه**.
اعتبار آزمایشی ۲۴ دلاری معمولاً **۴ تا ۶ ماه** دوام می‌آورد.

بدون کاهش منابع (پیش‌فرض Railway): حدود **۱۰ تا ۱۵ دلار در ماه**، یعنی کمتر از
دو ماه. به شدت پیشنهاد می‌شود منابع را طبق مرحلهٔ ۵ کاهش دهی.

نکته: اگر فقط وب‌پنل را می‌خواهی (بدون ربات تلگرام)، متغیر `WEB_ONLY=1` را تنظیم کن — مصرف به نصف می‌رسد. اما آن وقت کاربری به ربات دسترسی نخواهد داشت.

## عیب‌یابی

### خطاهای رایج `railway up`

**خطای `EACCES` هنگام `npm install -g`:**
ترمینال را به‌صورت ادمین باز کن (راست‌کلیک → Run as administrator).

**خطای `Unauthorized. Please login`:**
`railway login` را دوباره اجرا کن. اگر مرورگری باز نمی‌شود، از
`railway login --browserless` استفاده کن — یک کد می‌دهد که از دستگاه دیگه‌ای وارد می‌کنی.

**خطای `no project linked` یا `NOT_AUTHENTICATED`:**
`railway up` را از داخل خود پوشهٔ `aval-bot-railway` اجرا کن.
اگر قبلاً پروژه ساخته شده، اول `railway link` بزن.

**سوال Select a workspace / Select an environment:**
محیط پیش‌فرض (`production`) را انتخاب کن.

### خطاهای بعد از دیپلوی

**ربات بالا نمی‌آید ولی پنل کار می‌کند:**
توکن نامعتبر است. یک توکن جدید از BotFather بگیر، در تب Variables قرار بده و redeploy کن.

**پنل بالا نمی‌آید ولی ربات کار می‌کند:**
پورت اشتباه است. مطمئن شو `PORT` Railway با `WEB_PORT` یکسان است (Dockerfile این را خودکار تنظیم می‌کند).

**دیتابیس بعد از redeploy خالی است:**
Volume ساخته نشده یا مسیر آن `/app/data` نیست. مرحله ۴ را تکرار کن.

**خطای "Web Panel is not listening":**
این پیام مخصوص سرور است و روی Railway نادیده گرفته می‌شود. به Logs نگاه کن.
