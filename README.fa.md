# AVAL BOT — ربات فروش اشتراک VPN روی تلگرام

ربات فارسی فروش اشتراک VPN با پنل مدیریت تحت وب. کاملاً روی
[Railway](https://railway.app) اجرا می‌شود — بدون نیاز به سرور، بدون
systemd، بدون دانش لینوکس.

**یک پروسه، یک پورت** — ربات تلگرام و پنل وب در یک event loop واحد اجرا
می‌شوند، بنابراین در محدودیت رایگان Railway جا می‌گیرد.

---

## امکانات

- 💬 **ربات تلگرام** — کاربران محصولات را می‌بینند، اشتراک می‌خرند، پرداخت
  می‌کنند و لینک اشتراک + QR کد را دریافت می‌کنند
- 🌐 **پنل مدیریت وب** — مدیریت محصولات، سفارش‌ها، کاربران و تنظیمات از
  مرورگر (`https://<domain>/admin`)
- 🔄 **بک‌آپ خودکار** — هر چند ساعت یک‌بار، دیتابیس به صورت فایل فشرده در
  تلگرام شما ارسال می‌شود
- 💳 **پرداخت دستی** — کاربر رسید می‌فرستد، ادمین تأیید می‌کند، اشتراک
  خودکار تحویل داده می‌شود
- 🗄️ **اتصال محصولات به پنل** — هر محصول به یک inbound در پنل 3x-ui متصل
  می‌شود؛ حذف یا ویرایش محصول روی سفارش‌های قبلی اثری ندارد (از snapshot
  سفارش استفاده می‌شود)

---

## پیش‌نیازها

| مورد | نحوهٔ دریافت |
|---|---|
| یک پنل [3x-ui](https://github.com/MHSanaei/3x-ui) روی یک سرور | با یک inbound از قبل تنظیم شده |
| توکن ربات تلگرام | [@BotFather](https://t.me/BotFather) → `/newbot` |
| آیدی عددی تلگرام خودتان | [@userinfobot](https://t.me/userinfobot) |
| اکانت Railway | رایگان در [railway.app](https://railway.app) |

> **نکته:** این نسخهٔ Railway فقط خود ربات را اجرا می‌کند. پنل 3x-ui باید
> روی یک سرور در دسترس اینترنت باشد (هر هاستی، حتی یک سرور خانگی با tunnel).

## مراحل استقرار

### ۱) استقرار ریپو

در پنل Railway: **New Project → Deploy from GitHub repo** →
`AVAL_Bot_Railway` را جستجو کنید (این ریپو عمومی است). Railway به‌طور خودکار
`Dockerfile` را پیدا کرده و build می‌گیرد.

یا با Railway CLI:

```bash
railway up
```

### ۲) تنظیم متغیرها

در تب **Variables** سرویس:

| متغیر | الزامی | توضیح |
|---|---|---|
| `BOT_TOKEN` | ✅ | توکن از @BotFather |
| `ADMIN_IDS` | ✅ | آیدی عددی تلگرام شما (چندتایی را با کاما جدا کنید) |
| `WEB_ADMIN_PASSWORD` | ✅ | رمز ورود به پلن وب |
| `CARD_NUMBER` | ✅ | شماره کارتی که به کاربران نمایش داده می‌شود |
| `CARD_OWNER` | ✅ | نام صاحب کارت |
| `BACKUP_INTERVAL_HOURS` | ⬜ | پیش‌فرض `12` |

بقیه متغیرها مقدار پیش‌فرض دارند. لیست کامل در [`.env.example`](.env.example).

> **پنل‌های VPN از داخل خود ربات تنظیم می‌شوند**، نه با متغیر — پس از اولین
> استقرار به `/admin` بروید و پنل 3x-ui خود را آنجا اضافه کنید (آدرس، نام
> کاربری، رمز). سپس هر محصول را به یک inbound متصل کنید.

### ۳) ساخت Volume دائمی

**Settings → Volumes → Add Volume** → مسیر mount: `/app/data`

بدون این مرحله، هر بار redeploy کل دیتابیس (کاربران، سفارش‌ها، تنظیمات) پاک
می‌شود.

### ۴) دریافت آدرس عمومی

**Settings → Networking → Generate Domain**

آدرس پنل: `https://<domain-شما>/admin`

### ۵) بررسی

ربات پس از بالا آمدن، یک پیام «نصب با موفقیت» به `ADMIN_IDS` می‌فرستد که
آدرس پنل در آن است. دستور `/start` را به ربات بفرستید تا از جواب دادن آن
مطمئن شوید.

## امکانات پنل مدیریت

- **محصولات** — نام، مدت (روز)، حجم (گیگ)، قیمت. موجودی به کاربران نمایش
  داده نمی‌شود (طراحی نامحدود)
- **سفارش‌ها** — snapshot مدت و حجم در لحظهٔ خرید، تا ویرایش محصول بعداً روی
  سفارش‌های قبلی اثری نگذارد
- **کاربران** — موجودی کیف پول، ردیابی تست رایگان، مسدودسازی
- **بک‌آپ‌ها** — هر `BACKUP_INTERVAL_HOURS`، دیتابیس فشرده شده و در تلگرام
  ادمین ارسال می‌شود؛ فقط ۴۸ نسخهٔ آخر نگه داشته می‌شود
- **کنترل ربات** — روی Railway، start/stop/restart توسط خود Railway انجام
  می‌شود. ذخیرهٔ توکن/رمز جدید فقط ذخیره می‌شود؛ برای **اعمال** باید
  redeploy کنید

## هزینه روی اعتبار رایگان

با تنظیمات پیشنهادی، اعتبار رایگان **۴ تا ۶ ماه** دوام می‌آورد:

- **Settings → Resources**: `0.25 vCPU` و `256 MB` رم
- `BACKUP_INTERVAL_HOURS=12`

با منابع پیش‌فرض Railway (حدود ۱۰ تا ۱۵ دلار در ماه)، اعتبار ۲۴ دلاری در
کمتر از دو ماه تمام می‌شود.

## تفاوت با نسخهٔ سرور (VPS)

| امکان | نسخهٔ VPS (systemd) | نسخهٔ Railway |
|---|---|---|
| Start/Stop/Restart از پنل | ✅ | ❌ — Railway خودش پروسه را مدیریت می‌کند |
| حذف ربات از پنل | ✅ | ❌ |
| اعمال توکن/رمز جدید | فوری (restart) | نیاز به redeploy دارد |
| بک‌آپ تلگرام | ✅ | ✅ |
| پنل مدیریت وب | ✅ | ✅ |
| دیتابیس دائمی | ✅ | ✅ (با Volume) |

بخش «کنترل ربات و تنظیمات» در پنل، Railway را تشخیص می‌دهد و به‌جای خطا،
پیام مناسبی نشان می‌دهد.

## عیب‌یابی

**ربات جواب نمی‌دهد ولی پنل باز می‌شود:** `BOT_TOKEN` نامعتبر یا باطل شده.
یک توکن جدید از @BotFather بگیرید، در **Variables** قرار دهید و redeploy کنید.

**پنل باز نمی‌شود ولی ربات کار می‌کند:** پورت شناسایی نشده. `Dockerfile` به‌طور
خودکار `PORT` Railway را به `WEB_PORT` تبدیل می‌کند؛ اگر پرسید، `8090` وارد
کنید.

**دیتابیس بعد از redeploy خالی است:** Volume ساخته نشده یا روی `/app/data`
mount نیست. مرحلهٔ ۳ را تکرار کنید.

**Build شکست می‌خورد:** به **Deployments → View Logs** نگاه کنید. شایع‌ترین
دلیل، اشتباه تایپی در یک متغیر است، نه کد.

## ⚠️ امنیت

- هیچ‌وقت `BOT_TOKEN`، `WEB_ADMIN_PASSWORD` یا رمز پنل 3x-ui را در چت،
  issue یا commit ننویسید
- اگر یک اعتبارنامه لو رفت، **فوراً آن را باطل کنید** — @BotFather `/revoke`
  برای توکن، تغییر رمز پنل 3x-ui، و رمز جدید پنل وب
- از یک `WEB_ADMIN_PASSWORD` طولانی و تصادفی استفاده کنید

## توسعه

```bash
pip install -r requirements.txt
python -m pytest -q
```

این ریپو موازی با نسخهٔ VPS توسعه داده می‌شود؛ رفتار مخصوص کانتینر پشت
`IS_CONTAINER_PLATFORM` گارد شده تا همان `bot.py` در هر دو محیط کار کند.
